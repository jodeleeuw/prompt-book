## Anti-Patterns Verdict

**LLM assessment**: This does not read as AI-generated, and that is a real achievement. None of the absolute bans appear: no gradient text, no glassmorphism, no side-stripe borders, no hero-metric template, no identical card grids, no tiny uppercase eyebrow above every section, no numbered section scaffolding. The serif/sans split — `Iowan Old Style` for script content, system sans for chrome — is a committed decision that serves the content rather than decorating it, and it is the single strongest thing in the design.

One soft tell: the token is named `--paper` and the light body is `#faf8f4`. Warm near-white named `paper`/`cream`/`parchment` is the saturated 2026 AI default. Measured, this one sits just outside the flagged band (OKLCH L 0.980, C 0.0057, h 85 — the band is L 0.84–0.97, C < 0.06) and at essentially zero chroma it is a true off-white rather than a cream. The name is more of a tell than the colour, and here the metaphor is literal: it is a script on a page. Verdict: defensible, not a hit.

The genuine aesthetic weakness is the opposite of slop — it is under-commitment in one place. The rehearsal screen, the surface this product exists for, is styled almost identically to the library and settings screens. The one moment that should feel unmistakably different feels like another page of the same document.

## Overall Impression

The engineering is well ahead of the interaction design. Degraded modes, data safety, and state handling are better than most shipped apps: the import preview that refuses to strip anything silently, the token guard that stops a stale utterance dragging a paused run forward, the honest offline messaging. That is real craft.

What has not had the same attention is the *path* through the app. The core loop — "run this scene again" — costs five taps and forces you back through a setup screen you already completed. And the single most-used control in the product, the tap-anywhere-to-advance stage, is a `<div>` with a click handler: no keyboard, no focus, no accessible name.

The biggest opportunity is not visual. It is to make the app remember what you were doing and put you back in it.

## What's Working

1. **The import preview is a genuinely excellent piece of design.** Directions and parentheticals are shown struck through, individually reversible, and nothing is discarded until you confirm. Promoting a direction to a character even preserves text that would otherwise strip to nothing. Most apps would have silently dropped that content; this one made the loss visible and reversible. It is the clearest expression of "never lose the actor's words."

2. **Degraded states are honest and specific.** Offline, no microphone, refused permission, no voices — each has defined behaviour and copy that names what is lost *and* what still works ("Offline — your scripts are all here. Voice cueing needs a connection."). The silent-run fallback, where a device with no voices turns every line into one you read and tap past, is a real design decision rather than an error message.

3. **The typographic system is committed and content-led.** Serif for the script, sans for the chrome, small-caps speaker labels, near-monochrome. The script is genuinely the largest and most contrasted thing on screen. This is exactly what the brief asked for and it has been executed with discipline.

## Priority Issues

### [P1] Resuming a rehearsal costs five taps, and setup is re-shown every time

**Why it matters**: This is the core loop. An actor runs the same scene ten times in an evening. Every single time, the path is Library → script → Rehearse → Setup → Continue → Begin. Setup re-asks which character you are and which scenes you want, both of which are already stored on the script record and unchanged. `Continue` and `Begin` are two sequential commitment taps with different labels for one intention. The library gives no sign of what you were last working on.

**Fix**: When `userCharacterId` and `sceneIds` are already saved, `Rehearse` should go straight to the run, with `Set up` demoted to a secondary link on the script screen. Merge `Continue` and `Begin` — the tap that leaves setup is a user gesture and can unlock audio directly. Put the last-rehearsed script at the top of the library with its scene and position, so the first tap on launch resumes.

**Suggested command**: `/impeccable shape resume flow`

### [P1] The primary control of the entire app is a non-interactive `<div>`

**Why it matters**: `.stage` advances the run on click, and it is the control the product is built around. It is not focusable, has no `role`, no accessible name, and cannot be operated by keyboard. A screen-reader user gets no indication it is interactive; a keyboard user must find the small `Skip` button in the transport instead — which is labelled as a *skip*, not as *I have finished my line*, so it reads as a different action. There is also no live region, so nothing announces that the run has moved to your line.

**Fix**: Make the stage a real `<button>` (or add `role="button"`, `tabindex="0"`, an accessible name that changes with state, and Enter/Space handling). Add `aria-live="polite"` to the hint so turn changes are announced. Rename `Skip` to something honest about what it does in each state.

**Suggested command**: `/impeccable audit rehearsal screen`

### [P1] `--faint` fails contrast at 2.5:1 and is carrying real content

**Why it matters**: Measured against its own background, `--faint` is **2.53:1 in light and 2.91:1 in dark**, against a 4.5:1 requirement. It is not used decoratively — it renders the previous line in the rehearsal stage, the masked dots of a hidden line, and every stripped stage direction in the import preview. The masked dots are the *entire content* of a hidden line; if they are unreadable at a metre, the hidden rung of the memorisation ladder does not work. This directly contradicts the one accessibility priority you named.

**Fix**: Move `--faint` to at least 4.5:1 (roughly `#77706a` light, `#8a847b` dark) or stop using it for content and reserve it for hairlines. Then re-measure: `--muted` at 5.06:1 has little headroom either, and it carries every hint and speaker label.

**Suggested command**: `/impeccable colorize palette contrast`

### [P1] Native `confirm()`, `prompt()` and `alert()` break the system in four places

**Why it matters**: Deleting a script, deleting a scene, naming a new character during import, and every import error all hand off to unstyled browser dialogs. On Android these are Chrome system sheets — a different typeface, different buttons, different everything, appearing at the highest-stakes moments in the app. `prompt()` in particular is blocked or ignored in some embedded contexts, which would make "new character" silently do nothing. This is the clearest consistency violation in the product.

**Fix**: One inline confirmation pattern, used in all four places. For destructive actions prefer undo over confirm — delete immediately, offer "Undone" for a few seconds. For the character name, an inline text field in the row being edited.

**Suggested command**: `/impeccable harden dialogs and destructive actions`

### [P2] The rehearsal surface moves under you, and the bottom of it is contested

Three separate faults compound on the one screen that must be readable from a metre while you are speaking:

- **The line jumps vertically each turn.** `.stage` uses `align-items: center`, so the current line's position depends on whether a previous line is showing and how long both are. The eye has to re-find the text on every turn.
- **The transport can fall below the fold.** `.stage` is `flex: 1` inside a `min-height: 100dvh` column with no internal scroll, so a long speech grows the page and pushes `Back / Pause / Skip` off-screen. On a landscape tablet, where vertical space is already short, this will happen with ordinary monologues.
- **The offline banner covers the transport.** `.offline-banner` is `position: fixed; inset: auto 0 0` at `z-index: 10`; `.rehearsal` overrides the page's bottom padding down to `1.25rem`. When offline, the banner sits directly on top of the transport row.

**Fix**: Anchor the current line to a fixed baseline instead of centring; give `.stage` its own `overflow-y: auto` so long speeches scroll inside a stable frame; reserve space for the banner when it is visible rather than overlaying.

**Suggested command**: `/impeccable adapt rehearsal screen for landscape tablet`

## Persona Red Flags

**Nadia (the actor on her feet — project persona)**: Standing a metre back, mid-speech, holding a script. The line she is reading changes vertical position on every turn, so she loses her place each time the app speaks. On a hidden-level run, her line renders in `--faint` at 2.5:1 — at that distance and in a dim room, the dots are effectively invisible, which is the one thing that had to work. Her `Peek` button appears and disappears from the transport depending on state, so `Skip` shifts position and her thumb lands on the wrong control. She cannot start rehearsing without picking the phone up and making five taps.

**Alex (power user)**: No keyboard path to the primary action at all. Re-confirms setup every session for a script he has run twenty times. No way to jump to a specific line or scene mid-run — only `Back` one step at a time, so recovering from an accidental double-advance late in a scene means tapping `Back` repeatedly. No bulk select on the scenes list.

**Sam (accessibility-dependent)**: The main control is an unlabelled `div`; the run is effectively unusable by keyboard or screen reader. No live region announces whose turn it is. `--faint` content fails AA outright. The voice chip communicates microphone state through a coloured dot plus text — the text saves it, but the pulsing dot is the only *motion* cue and there is no `prefers-reduced-motion` alternative for it beyond disabling the animation.

**Riley (stress tester)**: Imports a PDF-pasted script where two speeches ran together on one line — and discovers there is no way to edit line text, ever. The only recourse is to delete the whole script and re-import. Toggles the format select to check what Fountain does, and loses every correction made so far to a note they had already scrolled past. Refreshes mid-rehearsal and lands back at the library with the run lost.

## Minor Observations

- The library meta line reads "48 lines" — the total including every other character. The number an actor cares about is how many are *theirs*. The app knows this after first setup.
- The empty state says "No scripts yet" and explains the preview, but never says what a script file should look like, and `samples/` is invisible from inside the app.
- Setup lists raw platform voice names ("Microsoft David — English (United States)"). On Android that list can run past twenty entries with no grouping.
- Editing chrome (`↑ ↓ ×`) sits permanently on every scene header in the script view, on what is otherwise a reading surface.
- `.title-input` is an inline-editable field with no label, no edit affordance, and no save confirmation — you type, blur, and nothing tells you it took.
- Fluid `clamp()` sizing on `.title` in the library is the brand-register reflex; product UI wants a fixed rem scale. On `.stage .current` fluid sizing is justified and should stay.
- There is essentially no motion in the app. Line changes are instant swaps. A 150–200ms crossfade on the stage would both soften the jump and convey state — this is the one place motion would earn its place.
- Import shows a `<select>` on all 100 lines when the parser is right about ~95 of them. Passive classification with tap-to-correct would invert that ratio.

## Questions to Consider

- What if opening the app put you straight into the scene you were last running, and the library were something you visited only to add a script?
- The app judges exactly one thing — when a line ends. What would it look like if the rehearsal screen were designed *only* around that moment, and everything else lived elsewhere?
- Hidden mode renders your line as dots you cannot read from a metre away. Is the dot row actually serving recall, or would the line's shape be better carried by something else entirely — length, punctuation, a bar per word?
- What would a confident version of the rehearsal screen look like if it did not have to resemble the rest of the app?
